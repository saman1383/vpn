# نصب خودکار ویرا روی سرور

> **مهم:** این نصاب فقط وب‌سایت React و پنل‌های نمایشی را اجرا می‌کند؛ سرور VPN، دیتابیس، درگاه بانکی یا احراز هویت ایجاد نمی‌کند. مسیر `/#admin` عمومی است. داده واقعی، رمز عبور و کلید API وارد نکنید.

## پیش‌نیازها

- سرور Linux با دسترسی `sudo`؛ برای نصب خودکار پیش‌نیازها، Ubuntu 22.04/24.04 یا Debian 12/13 با systemd توصیه می‌شود.
- حداقل پیشنهادی: ۱ هسته CPU، ۲ گیگابایت RAM و ۳ گیگابایت فضای آزاد برای ایمیج‌ها و مرحله build.
- اینترنت برای مخزن بسته‌های سیستم‌عامل، Docker Hub و npm.
- `git` برای دریافت پروژه. اگر موجود نیست: `sudo apt-get update && sudo apt-get install -y git`.
- برای HTTPS: یک دامنه با رکورد A درست و در صورت داشتن AAAA، IPv6 صحیح. پورت‌های TCP 80 و 443 باید آزاد و از اینترنت قابل دسترسی باشند.

نصاب DNS و فایروال را تغییر نمی‌دهد، وب‌سرورهای فعلی را متوقف نمی‌کند و پورت‌های اشغال‌شده را به زور آزاد نمی‌کند. روی سروری که قبلاً Nginx، Apache یا Caddy دارد، پیش از استفاده از حالت دامنه، تنظیم reverse proxy موجود را بررسی کنید. نصب Docker ممکن است مطابق رفتار بسته‌های سیستم‌عامل، تنظیمات شبکه Docker را ایجاد کند.

## ۱. دریافت پروژه

تا پیش از ادغام Pull Request، نسخه جاری روی شاخه زیر است:

```bash
git clone --branch arena/2261bea4-vpn https://github.com/saman1383/vpn.git vira
cd vira
```

اسکریپت `install.sh` را قبل از اجرای دسترسی root مطالعه کنید. از اجرای مستقیم کد ناشناس با الگوی `curl | bash` استفاده نشده است.

## ۲. بررسی بدون نصب

```bash
bash install.sh --dry-run
```

برای بررسی تنظیم دامنه:

```bash
bash install.sh --dry-run \
  --domain vpn.example.com \
  --email owner@example.com
```

این حالت فقط آرگومان‌ها و وجود فایل‌های لازم را بررسی و برنامه نصب را چاپ می‌کند؛ Docker، DNS، وضعیت دامنه یا آزادبودن پورت‌ها را آزمایش نمی‌کند و هیچ فایلی ایجاد نمی‌کند.

## ۳. نصب با IP و HTTP

```bash
sudo bash install.sh --yes
```

پس از موفقیت، سایت روی `http://SERVER_IP:8080` باز می‌شود. در صورت لزوم، پورت 8080 را در فایروال خود اجازه دهید.

انتخاب پورت یا نام نصب متفاوت:

```bash
sudo bash install.sh --yes --port 8090 --name vira-demo
```

گزینه `--yes` اجازه نصب غیرتعاملی را می‌دهد. بدون آن، تأیید از ترمینال دریافت می‌شود. برای استفاده از Docker نصب‌شده و جلوگیری از نصب بسته‌های Docker:

```bash
sudo bash install.sh --yes --skip-docker-install
```

اگر Docker/Compose موجود نباشند، این حالت با خطا متوقف می‌شود. این گزینه فقط نصب بسته‌ها را غیرفعال می‌کند؛ اگر daemon خاموش باشد، نصاب همچنان راه‌اندازی آن با systemd را امتحان می‌کند. روی توزیع‌های دیگر ابتدا Docker و Compose را مطابق مستندات رسمی نصب کنید.

## ۴. نصب با دامنه و HTTPS خودکار

دامنه و ایمیل نمونه را با مقادیر خود جایگزین کنید:

```bash
sudo bash install.sh --yes \
  --domain vpn.example.com \
  --email owner@example.com
```

نصاب:

1. پارامترها را اعتبارسنجی می‌کند و برای جلوگیری از اجرای هم‌زمان، قفل پروژه می‌گیرد.
2. در صورت نیاز Docker و Compose را از مخزن بسته‌های توزیع نصب و Docker daemon را راه‌اندازی می‌کند.
3. وب‌سایت را داخل ایمیج Node 22 با `npm ci` و `npm run build` می‌سازد؛ نصب Node روی میزبان لازم نیست.
4. فایل خروجی را با Nginx، کاربر غیر root، فایل‌سیستم فقط‌خواندنی و دسترسی‌های محدود اجرا می‌کند.
5. در حالت دامنه، Caddy را برای reverse proxy و دریافت/تمدید خودکار گواهی اجرا می‌کند.
6. حداکثر حدود ۶۰ ثانیه، پاسخ داخلی HTTP از `/healthz` را بررسی می‌کند.

در حالت HTTPS، پورت مستقیم وب روی `127.0.0.1:8080` محدود می‌شود و ورودی عمومی از پورت 443 عبور می‌کند. گواهی و تنظیمات Caddy در volumeهای Docker باقی می‌مانند.

**موفقیت health check داخلی به معنای تأیید HTTPS عمومی نیست.** صدور گواهی به DNS، بازبودن پورت‌ها، دسترسی سرور به ACME و محدودیت‌های صادرکننده وابسته است. برای تأیید، آدرس `https://YOUR_DOMAIN` را در مرورگر باز و لاگ proxy را بررسی کنید. نصاب ادعای موفقیت صدور گواهی نمی‌کند.

## مدیریت نصب

تنظیمات هر نصب در `.deploy/NAME.env` با مجوز محدود ذخیره می‌شود. این پوشه وارد Git یا image نمی‌شود. برای مثال، نام پیش‌فرض `vira` است.

### مشاهده وضعیت و لاگ

دستورهای زیر برای Docker Compose نسخه جدید نوشته شده‌اند. اگر سیستم شما از نسخه قدیمی استفاده می‌کند، `docker compose` را با `docker-compose` جایگزین کنید. دستورات را از پوشه پروژه اجرا کنید.

```bash
sudo docker compose -p vira -f compose.yaml --env-file .deploy/vira.env ps
sudo docker compose -p vira -f compose.yaml --env-file .deploy/vira.env logs --tail=100 web
sudo docker compose -p vira -f compose.yaml --env-file .deploy/vira.env --profile https logs --tail=100 proxy
```

### به‌روزرسانی

ابتدا تغییرات محلی کد را بررسی و در صورت لزوم پشتیبان بگیرید؛ سپس کد جدید را با Git دریافت و نصاب را **با همان نام، دامنه، ایمیل و پورت قبلی** اجرا کنید. نصاب خودش `git pull` انجام نمی‌دهد و نباید بدون بررسی، نسخه جدید را اجرا کرد.

```bash
git pull --ff-only origin arena/2261bea4-vpn
sudo bash install.sh --yes --domain vpn.example.com --email owner@example.com
```

مرحله build پیش از جایگزینی کانتینر فعلی انجام می‌شود. اگر build شکست بخورد، سرویس فعلی تغییر نمی‌کند. این نصاب rollback خودکار یا تضمین بدون قطعی ندارد؛ اگر راه‌اندازی کانتینر جدید شکست خورد، لاگ‌ها را بررسی و نسخه سالم کد را مجدداً مستقر کنید.

اجرای مجدد با گزینه‌های متفاوت، تنظیمات همان پروژه را تغییر می‌دهد. اجرای بدون `--domain`، پروکسی HTTPS قبلی همان پروژه را متوقف می‌کند و نصب را به حالت HTTP می‌برد؛ بنابراین گزینه‌های قبلی را حفظ کنید. نصب‌هایی با نام پروژه متفاوت مستقل‌اند، ولی نباید پورت‌های عمومی یکسان داشته باشند.

اگر نام Compose انتخابی با کانتینرهای نامرتبط برخورد کند، نصاب از ادامه خودداری می‌کند. در این حالت نام دیگری با `--name` انتخاب کنید.

### توقف بدون حذف داده گواهی

```bash
sudo docker compose -p vira -f compose.yaml --env-file .deploy/vira.env --profile https down
```

از گزینه `-v` استفاده نکنید، مگر آنکه عمداً بخواهید volumeهای گواهی نیز پاک شوند. نصاب Docker یا فایل‌های سایر سرویس‌های میزبان را حذف نمی‌کند. لاگ کانتینرها به ۳ فایل ۱۰ مگابایتی برای هر سرویس محدود شده‌اند.

## عیب‌یابی

- **Port is already allocated:** پورت در اختیار سرویس دیگری است. برای HTTP از `--port` متفاوت استفاده کنید. برای HTTPS عمومی، پورت‌های 80/443 باید آزاد باشند یا پروکسی فعلی را به‌صورت دستی تنظیم کنید.
- **Cannot contact Docker daemon:** وضعیت سرویس `docker` و مجوزهای کاربر را بررسی کنید؛ نصاب با `sudo` اجرا می‌شود.
- **خطای دریافت image یا npm:** دسترسی سرور به Docker Hub، registry.npmjs.org و مخزن بسته‌های سیستم‌عامل را بررسی کنید. نصاب mirror نامطمئن یا دورزدن اعتبارسنجی TLS اضافه نمی‌کند.
- **HTTPS فعال نمی‌شود:** رکوردهای A/AAAA، فایروال و لاگ Caddy را بررسی کنید. پورت 8080 داخلی جایگزین ورودی ACME روی 80/443 نیست.
- **ادمین داده‌های پنل کاربر را نشان نمی‌دهد:** این نسخه فرانت‌اند است؛ داده‌های نمونه ادمین مستقل از داده‌های پنل کاربری هستند.
- **build با کمبود حافظه متوقف می‌شود:** حداقل پیشنهادی RAM را بررسی کنید یا ساخت را روی ماشین قوی‌تر انجام دهید.

## تست‌ها و محدودیت ارزیابی

`npm test` شامل بررسی syntax اسکریپت، dry-run، اعتبارسنجی پورت/دامنه/ایمیل و جلوگیری از تزریق خط جدید در فایل env است. ساخت React و تست‌های مرورگری جداگانه اجرا می‌شوند. نصب کامل Docker و صدور واقعی گواهی به یک میزبان و دامنه واقعی نیاز دارند؛ dry-run جایگزین این آزمون نیست.
